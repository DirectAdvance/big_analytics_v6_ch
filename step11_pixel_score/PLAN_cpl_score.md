# ПЛАН: новый скор CPL-качества (0.3–3) для big_analytics_pixel_score

## Суть

Добавить колонку `cpl_score` в `public.big_analytics_pixel_score` (и `public.pixel_score`).
Скор отражает **качество кампании по CPL на каждом этапе воронки** относительно среднего по домену.

Не заменяет `weight` (атрибуция) — дополняет его.

---

## Формула

### Шаг 1. Domain avg (за последние 3 полных календарных месяца, по всем кампаниям домена)

```sql
CPL_avg_квал    = SUM(total_cost) / NULLIF(SUM(kval),    0)  WHERE kval    > 0
CPL_avg_визит   = SUM(total_cost) / NULLIF(SUM(priezd),  0)  WHERE priezd  > 0
CPL_avg_продажа = SUM(total_cost) / NULLIF(SUM(prodazhi),0)  WHERE prodazhi> 0

cnt_avg_квал    = AVG(kval)     -- только строки с kval    > 0
cnt_avg_визит   = AVG(priezd)   -- только строки с priezd  > 0
cnt_avg_продажа = AVG(prodazhi) -- только строки с prodazhi> 0
```

Источник: `big_analytics_direct`, данные за тот же месяц, что и строка `pixel_score`
(апрель → domain avg из апреля, март → из марта, май → из мая),
`_source_table IN ('direct','crop_targeting','tp8','tp9','tp10')`.
Фильтр в GROUP BY: `DATE_TRUNC('month', "Date") = ps.month` (через JOIN по месяцу).

### Шаг 2. Score каждого этапа (для конкретной кампании)

```
для каждого этапа (квал, визит, продажа):

  если count_campaign > 0:
      CPL_campaign = total_cost / count_campaign
      score_stage  = clamp(CPL_avg_domain / CPL_campaign, 0.3, 3.0)
      статус       = 'данные'

  если count_campaign = 0:
      если total_cost < 3 × CPL_avg_domain:
          score_stage = 1.0
          статус      = 'ждём'         ← мало потрачено, ждём конверсий
      иначе:
          score_stage = 0.3
          статус      = 'плохо'        ← потрачено достаточно, результата нет
```

### Шаг 3. Вес каждого этапа

```
если статус = 'ждём':
    w_stage = 0   ← этап исключён из расчёта

если статус = 'плохо':
    w_stage = 1.0 ← минимум, участвует со штрафным score=0.3

если статус = 'данные':
    w_stage = clamp(count_campaign / cnt_avg_domain, 1.0, 3.0)
              ← больше событий чем avg → выше вес → этап влияет сильнее
```

Диапазон весов 1–3 (не 0.3–3): все активные этапы всегда вносят вклад.

### Шаг 4. Итоговый скор

```
cpl_score = SUM(w_i × score_i) / SUM(w_i)
cpl_score = clamp(cpl_score, 0.3, 3.0)
```

Если все этапы в статусе 'ждём' (w_total = 0) → `cpl_score = 1.0` (нейтральный).

## Примеры

### Domain avg (autopark-spb.ru)

```
CPL_avg_квал    = 24 000 ₽    cnt_avg_квал    = 10
CPL_avg_визит   = 75 000 ₽    cnt_avg_визит   =  5
CPL_avg_продажа = 558 000 ₽   cnt_avg_продажа =  2
```

### Пример 1 — полная воронка

`spend=300к, квал=20, визит=6, продажа=1`

| Этап | CPL | ratio | score | w | w×score |
|------|-----|-------|-------|---|---------|
| квал | 15к | 24к/15к=1.6 | 1.6 | clamp(20/10,1,3)=2.0 | 3.20 |
| визит | 50к | 75к/50к=1.5 | 1.5 | clamp(6/5,1,3)=1.2 | 1.80 |
| продажа | 300к | 558к/300к=1.86 | 1.86 | clamp(1/2,1,3)=1.0 | 1.86 |

```
cpl_score = (3.20 + 1.80 + 1.86) / (2.0 + 1.2 + 1.0) = 6.86 / 4.2 = 1.63 ✅
```

### Пример 2 — нет продаж (мало потрачено, ждём)

`spend=150к, квал=6, визит=2, продажа=0`
Порог продажи: 3 × 558к = 1 674к. 150к < 1 674к → статус='ждём', w=0

| Этап | CPL | score | w |
|------|-----|-------|---|
| квал | 25к | 0.96 | clamp(6/10,1,3)=1.0 |
| визит | 75к | 1.0 | clamp(2/5,1,3)=1.0 |
| продажа | — | — | **0 (ждём)** |

```
cpl_score = (1.0×0.96 + 1.0×1.0) / (1.0 + 1.0) = 1.96 / 2.0 = 0.98
```

### Пример 3 — потрачено много, продаж нет (плохо)

`spend=2 000к, квал=40, визит=8, продажа=0`
2 000к ≥ 1 674к → статус='плохо', score=0.3, w=1.0

| Этап | CPL | score | w |
|------|-----|-------|---|
| квал | 50к | 0.48 | clamp(40/10,1,3)=3.0 |
| визит | 250к | 0.30 | clamp(8/5,1,3)=1.6 |
| продажа | 0 данных | 0.30 (плохо) | 1.0 |

```
cpl_score = (3.0×0.48 + 1.6×0.30 + 1.0×0.30) / (3.0+1.6+1.0)
          = (1.44 + 0.48 + 0.30) / 5.6 = 2.22 / 5.6 = 0.40 ❌
```

### Пример 4 — реальный разбор по группам: multicar-116.ru, апрель 2026

Исходные данные из PBI матрицы:
```
Обращения: 152  |  Заявки: 106  |  Квал: 70  |  Приезд: 10  |  Продажи: 0
pixel_kol_vo_домена: 1 026
cpl_avg_квал: 12 670₽  |  cpl_avg_визит: 91 855₽  |  cpl_avg_продажа: —
cpl_кам_квал: 38 055₽  |  cpl_кам_визит: 57 757₽  |  cpl_кам_продажа: —
cpl_score: 1,97
```

#### Группа 1 — Воронка (что случилось в CRM)

| Колонка | Что | multicar |
|---|---|---|
| Обращения | Сырые лиды из CRM | 152 |
| Заявки | После коррекций (убраны дубли, отказы) | 106 |
| Квал | Прошли квалификацию | 70 |
| Приезд | Приехали в салон | 10 |
| Продажи | Купили | 0 |

#### Группа 2 — Пиксель (что видел счётчик на сайте)

`pixel_kol_vo_домена = 1 026` — пиксель зафиксировал 1 026 конверсий с сайта multicar-116.ru за месяц. Общий пул — все кампании домена вместе.

#### Группа 3 — Бенчмарк домена (cpl_avg_*)

Среднее по домену multicar-116.ru за тот же месяц (апрель), по всем кампаниям домена:

```
cpl_avg_квал    = SUM(расходы) / SUM(квал)    = 12 670₽ за 1 квал
cpl_avg_визит   = SUM(расходы) / SUM(приезд)  = 91 855₽ за 1 визит
cpl_avg_продажа = NULL → по домену < 3 продаж, бенчмарк ненадёжен
```

Мерило — только внутри одного домена (межсалонное сравнение бессмысленно: haval vs toyota — разные ценники).

#### Группа 4 — CPL кампании (cpl_кам_*)

CPL конкретной кампании (контекст-направление):

```
cpl_кам_квал    = расходы / квал    = 38 055₽
cpl_кам_визит   = расходы / приезд  = 57 757₽
cpl_кам_продажа = NULL → продажи = 0
```

> PBI показывает агрегат направления (несколько кампаний). Скор считается по каждой кампании
> отдельно в SQL, затем взвешивается. Поэтому агрегированный cpl_кам ≠ напрямую пересчитывает в score.
> Визит сходится: 91 855 / 57 757 = 1.59 ≈ score_визит 1.66 ✓
> Квал не сходится на агрегате — это норма.

#### Группа 5 — Скор по этапам

```
score_этапа = CLAMP( cpl_avg_домена / cpl_кам, 0.3, 3.0 )
```

На уровне отдельных кампаний (не агрегат):

| Этап | events кам | avg домена | w = clamp(ev/avg, 1, 3) | score | w × score |
|---|---|---|---|---|---|
| квал | 58 | ~19 | clamp(3.05) = **3.0** | 2.18 | 6.54 |
| визит | 8 | ~3.9 | clamp(2.05) = **2.05** | 1.66 | 3.41 |
| продажа | 0 | — | **0** (ждём) | 1.0 | — |

Статус продажи «ждём»: продаж=0, но потрачено < 3 × cpl_avg_продажа → нейтральный score=1.0, вес=0 (не влияет).
Статус «плохо» (если потрачено ≥ порога): score=0.3, вес=1.0 (штраф участвует).

#### Итог

```
cpl_score = (6.54 + 3.41) / (3.0 + 2.05) = 9.95 / 5.05 = 1.97 ✅
```

Смысл весов: квал имеет 58 событий при среднем ~19 → в 3× больше нормы → вес 3.0 (максимум).
Визит — чуть выше нормы → вес 2.05. Кампания с большим объёмом данных влияет на скор сильнее — защита от выводов на 1–2 событиях.

**Результат: 1.97 — хорошая кампания (1.5–2.5). По квалу работает в 2.18× эффективнее среднего по домену.**

## Как работает диапазон 0.3–3.0

**0.3–3.0 — это не коэффициент, а CLAMP (пол и потолок) на результат деления:**

```
score = GREATEST(0.3, LEAST(3.0, CPL_avg_домена / CPL_кампании))
```

| Граница | Когда срабатывает | Что значит |
|---------|------------------|-----------|
| **Потолок 3.0** | CPL кампании в 3× и более ниже avg | «отличная», но не бесконечно |
| **Пол 0.3** | CPL кампании в 3× и более выше avg | «плохая», но не штраф ×10 |

Пример: если кампания тратит в 10× больше домен-среднего на квал → ratio=0.1, но score=**0.3** (мягкий пол, не 0.1).

В примерах 1 и 2 clamp не срабатывает — все ratio уже в диапазоне [0.3, 3.0]. В примере 3:
- визит: 75к/250к = 0.30 → ровно на полу
- продажа (статус «плохо»): принудительно score=0.30

Clamp применяется дважды: к каждому stage score и к итоговому `cpl_score`.

## Шкала интерпретации

| cpl_score | Интерпретация |
|-----------|---------------|
| 2.5–3.0 | Отличная кампания — CPL в 2.5–3х ниже avg домена |
| 1.5–2.5 | Хорошая — дешевле среднего |
| 0.8–1.5 | Средняя — около avg |
| 0.5–0.8 | Слабая — дороже среднего |
| 0.3–0.5 | Плохая — CPL в 2–3х выше avg или тратим много без результата |

## Где считается

**Период:** данные за тот же месяц что и строка в `pixel_score` — каждый месяц получает свои коэффициенты.
Апрель → domain avg апреля, март → domain avg марта, май → domain avg мая.
**Гранулярность:** одна строка на (кампания, месяц) — скор зависит от месяца.
**Хранение:** в таблице `pixel_score` колонка `cpl_score NUMERIC(4,2)`.

## Нюансы реализации

1. **Дробные значения в pixel_score:** kval/priezd/prodazhi в `big_analytics_pixel_score` — дроби (атрибутированные доли). Для CPL расчёта использовать `big_analytics_direct` (целые числа), не `big_analytics_pixel_score`.

2. **Domain avg только внутри домена:** межсалонное сравнение бессмысленно (haval-novgorod vs toyota-spb — разные ценовые категории).

3. **Минимальный порог для надёжного domain avg:**
   - Если по домену < 3 продаж за период → `CPL_avg_продажа = NULL` → у всех кампаний статус='ждём' по продажам
   - Если по домену < 5 визитов за период → аналогично для визитов

4. **Период скора = период данных:** `cpl_score` рассчитывается на данных за тот же месяц что и строка `pixel_score`. Разные месяцы одной кампании могут получить разные `cpl_score` — domain avg считается независимо по каждому месяцу.
