# Расследование: креативы Директа x CTR x цели

Статус: план расследования, реализации нет.

Цель: понять, что можно честно анализировать по конкретному креативу Директа в BA6, и подготовить
основание для будущего отчёта VictoryAds.

## Граница утверждений

Можно измерять по `banner_id`:

- показы;
- клики;
- CTR;
- расход;
- цели Директа `all_forms`;
- цену `all_forms`;
- `CRM заказ оплачен`, только если будет найден реальный источник на уровне `banner_id`.

Нельзя утверждать без отдельной связки:

- конкретный заголовок дал продажу;
- конкретный текст дал приезд, добро или продажу;
- одна вариация заголовка внутри `ResponsiveAd` лучше другой, если Яндекс отдаёт статистику только
  по объявлению целиком.

Если полная BA/CRM-воронка доступна только на уровне `AdGroupId` или `CampaignId`, используем её
как контекст группы/кампании, а не как доказательство эффективности конкретного заголовка.

## Известно на старте

- Сырой источник текстов: `raw_data.direct_cookie_ads_texts_master`.
- Совместимая view метрик: `ad_analytics.bi_yandex_direct_ads_texts`.
- Размерность текстов: `ad_analytics.bi_Dim_AdText`.
- В `raw_data.direct_cookie_ads_texts_master` есть `client_login`, `campaign_id`, `adgroup_id`,
  `banner_id`, `banner_title`, `banner_body`, `banner_href`, `banner_status`, `banner_type`,
  `shows`, `clicks`, `cost`, `goals`.
- В `bi_yandex_direct_ads_texts` сейчас есть `goal_all_forms`; `goal_crm_order_paid` в коде view
  заполнен нулём, поэтому его нужно отдельно проверить как источник, а не считать готовым фактом.

## Вопросы расследования

1. Есть ли в BA6 реальная цель `CRM заказ оплачен` на уровне `banner_id`?
2. Достаточно ли ключей `client_login + campaign_id + ad_group_id + banner_id + scope_from` для
   стабильного отчёта по креативам?
3. На какой гранулярности можно честно связать креативы с нашей воронкой:
   `banner_id`, `ad_group_id` или `campaign_id`?
4. Какие признаки заголовков и текстов чаще встречаются у winner-креативов?
5. Какие признаки чаще встречаются у loser-креативов?
6. Какие правила можно потом вернуть в генератор заголовков/текстов?

## План расследования

### 1. Проверить источники и свежесть

- `raw_data.direct_cookie_ads_texts_master`: даты, логины, баннеры, поля целей.
- `ad_analytics.bi_yandex_direct_ads_texts`: фактические колонки и формулы.
- `ad_analytics.bi_Dim_AdText`: полнота `title` / `text` / `status` / `banner_href`.
- Проверить свежесть по максимальным датам таблиц, не по `etl_runs`.

### 2. Проверить цель `CRM заказ оплачен`

- Найти, есть ли raw/view/table с этой целью на `banner_id`.
- Если есть: описать ключи и пример join.
- Если нет: зафиксировать, что первый отчёт считает только `all_forms` на уровне креатива.

### 3. Собрать тестовый срез

Один логин, последние 30 дней, уровень `banner_id`:

- `client_login`;
- `campaign_id`;
- `ad_group_id`;
- `banner_id`;
- `title`;
- `text`;
- `ad_type`;
- `status`;
- `impressions`;
- `clicks`;
- `ctr`;
- `cost`;
- `goal_all_forms`;
- `cost_per_all_form`;
- `goal_crm_order_paid`, если реально найден.

### 4. Сравнить с BA/CRM-воронкой

- Проверить join к `big_analytics_full` / `fact_big_analytics` по `CampaignId` и `AdGroupId`.
- Посчитать, где воронка доступна только на группе/кампании.
- Явно разделить:
  - метрики креатива;
  - контекст группы;
  - контекст кампании.

### 5. Разметить признаки текстов

Стартовый словарь:

- скидка;
- кредит;
- трейд-ин;
- КАСКО;
- первый взнос;
- срочность;
- город;
- бренд;
- модель;
- наличие;
- подарок;
- CTA;
- цена или платёж;
- гарантия;
- тест-драйв;
- рассрочка;
- одобрение;
- выгода в рублях;
- выгода в процентах.

Правило расширения: все часто встречающиеся формулы, слова и УТП из winner/loser-креативов
добавляются в словарь расследования. Стартовый список не ограничивает анализ.

### 6. Определить winners и losers

Минимальные критерии для первого прохода:

- winner CTR: высокий CTR при достаточных показах;
- winner forms: низкая цена `all_forms` при достаточном расходе;
- loser CTR: низкий CTR при достаточных показах;
- loser forms: расход есть, `all_forms` нет или цена сильно хуже медианы.

Пороговые значения сначала подбираются по распределению тестового логина, не задаются константами.

### 7. Итоговый отчёт расследования

Отчёт должен ответить:

- можно ли считать эффективность креативов на уровне `banner_id`;
- есть ли `CRM заказ оплачен` на уровне `banner_id`;
- какие join-ключи подтверждены;
- где теряется точность;
- какие признаки чаще у winners;
- какие признаки чаще у losers;
- какие признаки стоит усилить или запретить в генераторе;
- какой read-only отчёт первым добавить в VictoryAds.

## Первый результат

Короткий markdown-отчёт по одному логину за 30 дней:

- схема источников;
- SQL-проверки;
- пример таблицы креативов;
- список подтверждённых и неподтверждённых связок;
- решение, какую гранулярность брать для MVP.

## Вне расследования

- не менять pipeline;
- не создавать новые таблицы;
- не менять Power BI;
- не писать генератор;
- не применять выводы к созданию кампаний до подтверждения на данных.
