### Canary-SELECT (guardrail) — в норме 0 строк
```sql
-- CANARY: дедупликация посевов. Норма = 0 строк.
-- Запускать после обновления crop_targeting_api_telegain_lead и gsheets_..._leads.
SELECT
    DATE_TRUNC('month', "Date")::date AS month,
    "CampaignName" AS channel, domain,
    ROUND(gsheets_cost,0) gsheets_rub, ROUND(api_cost,0) api_rub,
    ROUND(gsheets_cost+api_cost,0) potential_double
FROM (
    SELECT "Date","CampaignName",domain,
        SUM(CASE WHEN src='gsheets' THEN cost ELSE 0 END) gsheets_cost,
        SUM(CASE WHEN src='api' THEN cost ELSE 0 END) api_cost
    FROM (
        SELECT TO_DATE(NULLIF(TRIM("Дата"),''),'DD.MM.YYYY') "Date",
               "Канал" "CampaignName", LOWER(TRIM("Сайт")) domain,
               NULLIF(total_cost,'')::numeric cost, 'gsheets' src
        FROM public.gsheets_crop_targeting_account_leads
        WHERE NULLIF(TRIM("Дата"),'') IS NOT NULL AND NULLIF(total_cost,'') IS NOT NULL
          AND TO_DATE(NULLIF(TRIM("Дата"),''),'DD.MM.YYYY') < '2026-05-01'
        UNION ALL
        SELECT "Date","CampaignName",domain,total_cost,'api'
        FROM public.crop_targeting_api_telegain_lead
        WHERE "Date" >= '2026-05-01' AND total_cost > 0
    ) c
    GROUP BY "Date","CampaignName",domain
    HAVING SUM(CASE WHEN src='gsheets' THEN cost ELSE 0 END) > 0
       AND SUM(CASE WHEN src='api' THEN cost ELSE 0 END) > 0
) s
ORDER BY month, potential_double DESC;
-- На 2026-06-04: 1 конфликт (vlzjest / carnew-vlg.ru / 2026-05-03).
```

## Вопрос 2 — заявки vs gsheets (янв–апр). 2208 посевных лидов

> Признак посева — `local_leads_all.utm_medium='posev'` (НЕ через pravilo_utm — там мусор `"UTM"='-'`).

| Статус | Лидов |
|---|---|
| Matched (точный ключ + точный месяц) | 1581 |
| Month-mismatch | 355 |
| Orphan-UTM (нет в pravilo_utm) | 256 |
| Пустой utm_campaign | 16 |

### Month-mismatch (355) — систематика, не хаос
87% (309/355) — расхождение ровно на 1 месяц. Механика: лид приходит в одном месяце,
расход занесён в реестр в соседнем (пред/пост-оплата размещения).
Крупное: `region116` (128 лидов, фев → расход мар/апр), `ufa_rb`+`bashkiriya_online` (156 лидов).
У многих UTM **февраль отсутствует** в реестре при наличии янв+мар — дыра в Google Sheet за февраль.

| Вариант матчинга | Matched | Прирост |
|---|---|---|
| Точный месяц (сейчас) | 1581 | — |
| **±1 месяц** | 1884 | **+303** |
| Любой месяц UTM | 1936 | +355 |

→ Рекомендация: **±1 месяц** (компромисс точность/возврат). «Любой месяц» рискует привязать к чужому периоду.

### Orphan-UTM (256, уник. 95)
- **Суффикс-нормализация** (_max/_vk/_tg/_storis/_vkstories): **+36** лидов (12 UTM).
  Примеры: `chp_samara_max → chp_samara`, `novosti_kazani_max → novosti_kazani`, `volgograd → volgograd_max`.
- **Fuzzy (опечатки/регистр):** ~25–30 лидов. Примеры: `atmosfera_beloyarskij_hmao ↔ atmosfera_beloiarskii_khmao`,
  `strlive_... ↔ strLive_...`, `chp_chelny1678 ↔ chp_chelny` (числовой суффикс), `chp_24_kumertau=25042026` (дата в UTM — мусор).
- **Реально новые каналы (нет нигде):** 37 UTM / **124 лида** — нужно дозаполнить реестр.
  Топ: `kazan_glavnoe` (16), `chp_sochi_max` (14), `naberezhnye_chelny_chs_max` (10), `netipchnyi_stvrp` (8).
- Разрез: **max 110 лидов / telegram 100 / vk 7** — Max и Telegram теряют больше всего.

### Пустой UTM (16) — все «Автоцентр на Жукова», март, source crmf_excel
utm_source=max, utm_campaign пуст. Брак разметки на стороне CRM/форм. Спасти можно только хрупкой
эвристикой (домен+источник+месяц) — по-хорошему чинить интеграцию CRM.

### Качество справочника pravilo_utm
1857 строк, 675 рабочих UTM, мусора `'-'` = 3. Главная проблема — **8 UTM маппятся в разные «утверждённые»**
(195 затронутых лидов): `zhest_vlg`(3 варианта), `region116`(2), `pyatigorsk_i_vse_kmb`(2) и др.
`region116` — самый болезненный (128 фев-лидов, маппинг плавает region116/region116_max).

## Вопрос 4 — заявки-сироты (нет расхода нигде)

| Брак разметки `victory`-домены | 0 | не воспроизвелось в текущих данных |

### Февральский «всплеск» — не дыра за февраль, а мультидомен
75 февраль-сирот (не 197). Топ: `1777_stvrp` (max, 20), `bashkiriya_online` (telegram, 13).
Причина: один UTM покрывает несколько доменов (`havaldrive-102.ru`, `newauto-102.ru`),
в gsheets заведена строка только для одного. Дозаполнение «за февраль» не поможет без правки логики/реестра.

### VK/Max — расход БЫЛ по апрель, с мая пропал

| янв | 287 922 | 668 378 |

### CPL-искажение (важно для отчётов)
`social_посевы` имеют `total_cost=NULL` (245 строк, 728 лидов). При GROUP BY `источник IN ('Max','VK')`:
| сценарий | leads | cost | CPL |
|---|---|---|---|
| с social_посевы (cost=NULL) | 1642 | 4 361 196 | **2 656 ₽** |
| только с расходом | 914 | 4 361 196 | **4 772 ₽** |
CPL занижается в **1.8×**. → фильтровать `cost IS NOT NULL` ИЛИ пометить `social_посевы` явным признаком.
Структурного задвоения лидов нет (`NOT EXISTS` в `_add_social_posev_to_crop_sql` защищает).
