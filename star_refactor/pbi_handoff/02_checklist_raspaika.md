## Этап 4. Создать 8 связей (single-direction, Dim 1 → факт *)

> Тип фильтрации: **single** (однонаправленная). Кратность: **один-ко-многим (1:*)**.
> Сторона «1» — dim, сторона «*» — факт. Cross-filter direction = Single.

### Связи для fact_big_analytics (таблица `big_analytics_full` в модели)
- [ ] 1. `Dim_Date[Date]`          → `big_analytics_full[Date]`
- [ ] 2. `Dim_Site[domain]`        → `big_analytics_full[domain]`
- [ ] 3. `Dim_Campaign[CampaignId]`→ `big_analytics_full[CampaignId]`
- [ ] 4. `Dim_AdGroup[AdGroupId]`  → `big_analytics_full[AdGroupId]`

### Связи для arp_fact (если завёл ARP)
- [ ] 5. `Dim_Date[Date]`          → `arp_fact[Date]`
- [ ] 6. `Dim_Site[domain]`        → `arp_fact[domain]`
- [ ] 7. `Dim_Campaign[CampaignId]`→ `arp_fact[CampaignId]`
- [ ] 8. `Dim_AdGroup[AdGroupId]`  → `arp_fact[AdGroupId]`

> ⚠️ Если на AdGroupId/CampaignId в факте есть NULL (звонки/SEO без группы) — PBI создаст
> «пустую» строку-член в dim. Это нормально, метрики не теряются. НЕ делай связь
> bi-directional — только single.

## Этап 5. Переназначить поля визуалов факт → dim (по 37 страницам)

> Скрипт `find_field_refs.py` выдал ~630 ссылок на поля, которые переедут в dim.
> Power BI **сам пересчитает** визуалы, если поле в факте удалить ДО переноса — но визуал
> сломается («поле не найдено»). Правильный порядок: сначала перетащить аналог из dim,
> потом убрать старое поле факта. Карта замен:

| Поле в визуале (было — факт) | Стало (dim) |
|---|---|
| салон, город, регион, тип_сайта, id_салона, направление, шаблон, site_quiz, проджект, менеджер, специалист, «Название crm», «марки авто», статус | **Dim_Site** |
| CampaignName, «номер кампании | название кампании», campaign_status, payment_model, account_login | **Dim_Campaign** |
| AdGroupName, adgroup_code, «номер группы | название группы», ag_part1..7, ag_part1_name, **неверный_кодер_new** | **Dim_AdGroup** |
| «День недели», week_start | **Dim_Date** |

- [ ] Пройтись по страницам (порядок — по `field_refs_report.csv`, начни с самых частых полей).
- [ ] claim / `(атрибуция)`-меры — **НЕ трогать**, остаются на факте.
- [ ] Срез заявка/визита — фильтр по `big_analytics_full[атрибуция]` (как было).

## Этап 6. Удалить дубль-колонки из факта (ТОЛЬКО после переноса всех визуалов)

> поэтому в самой таблице удалять нечего — они физически отсутствуют после смены source.
> Этот этап = убедиться, что в модели не осталось «битых» ссылок на отсутствующие поля факта.

- [ ] Открыть «Вид модели» → таблица `big_analytics_full` → проверить, что колонок-атрибутов

      ref на удалённую колонку → найти по `field_refs_report.csv` и заменить на dim-аналог.
