# step13_arrival — Воронка по дате визита

Строит таблицу `big_analytics_full_arrival` в БД `ad_analytics_bi`.

## Зачем

`big_analytics_full` группирует всё по **дате заявки** (created_date).
Эта таблица группирует прiezды и продажи по **дате фактического визита** (arrival_date).

Позволяет ответить на вопрос: *"Сколько клиентов приехало в январе?"* —
а не *"Сколько заявок с января в итоге превратилось в приезды?"*

## Структура

```
big_analytics_full_arrival
├── "Date"        — дата визита (arrival_date по правилам CRM)
├── domain        — домен сайта
├── "салон"       — салон
├── "город"       — город
├── "регион"      — регион
├── direction     — направление (только 'Авто')
├── "специалист"  — директолог
├── "статус"      — статус домена
├── source_type   — CRM-источник (plex_excel, crmf_excel, mega_crm_excel, marcar_crm_excel)
├── priezd        — визиты по дате приезда
├── prodazhi      — продажи по дате приезда
└── ... (korr, kval, nekorr, ne_otvechaet, filtr, nedozvon, priedet, dohod_do_kredita, dobro)
```

**Нет:** total_cost, Clicks, Impressions, CampaignId, AdGroupId — расходы привязаны к дате заявки.

## Модели атрибуции и CRM-группировка

### Две модели

| | Заявка (lead_date) | Визит (arrival_date) |
|---|---|---|
| Расходы | дата заявки (BAF) | дата заявки (BAF) — не меняется |
| Заявки | дата заявки (BAF) | дата заявки (BAF) — не меняется |
| Приезды | из BAF, поле `priezd` — привязан к заявке | из BAF_arrival, поле `priezd` — привязан к визиту |
| Продажи | из BAF, поле `prodazhi` — привязан к заявке | из BAF_arrival, поле `prodazhi` — привязан к визиту |
| Источник ЦРМ | BAF, поле `"Название crm"` — напрямую | справочник domain→CRM из BAF (см. ниже) |

**Следствие:** расходы и заявки одинаковы в обеих моделях. Приезды/продажи сдвигаются во времени (заявка в апреле → визит в мае). Итоговые суммы за длинный период сходятся (~1% погрешность).

### CRM-группировка в arrival-модели

`big_analytics_full_arrival` не содержит поле `"Название crm"` — только `source_type` и `domain`.

Для среза по ЦРМ в arrival-модели применяется двухэтапный подход:
1. Строится справочник `domain → CRM` из BAF через `MODE() WITHIN GROUP (ORDER BY "Название crm")` — берётся наиболее частое значение по домену
2. BAF_arrival джойнится к справочнику по `domain` → получает CRM-метку

### Почему итоги по CRM могут не совпадать

| Причина | Пример |
|---|---|
| Домен в двух CRM одновременно (gsheet_sites дубль) | Элит Авто домены числились и в АвтоСтайл — все arrival ушли в АвтоСтайл |
| Салон закрылся, домены перенесены в другую CRM | Элит Авто → АвтоСтайл с 01.11.2025 |
| Домены в BAF есть, в BAF_arrival нет | Новые домены без CRM-лидов |
| Нормальный сдвиг визита | Заявка в конце месяца, визит — в начале следующего |

## Правила даты визита по CRM

| CRM | Правило |
|---|---|
| crmf_excel | arrival_date из БД (заполнен ~100% у "Приехал") |
| mega_crm_excel | arrival_date из БД (заполнен ~100% у "Приехал") |
| plex_excel | created_date (Plex не фиксирует дату приезда) |
| marcar_crm_excel | gsheet_priezdi_marcar по ID заявки из ссылки; `source`-домен gsheet имеет приоритет над DB-доменом, если найден как Авто-домен |

## Power BI интеграция (26.05.2026)

Таблица подключена к `Большая аналитика_v00.pbip`.

На странице **"Модель атрибуции"** — слайсер "По дате заявки / По дате визита".
При выборе "По дате визита" матрица показывает данные из `big_analytics_full_arrival`.

**Меры в `big_analytics_full`:**
- `Приездов (атрибуция)` — SWITCH между `priezd` из двух таблиц
- `Продаж (атрибуция)` — SWITCH между `prodazhi` из двух таблиц
- `CPL приезда`, `CPL продажи`, `CR приезд`, `CR продажи` — обновлены, используют SWITCH-меры

Фильтр строк матрицы (по салону) передаётся через `TREATAS(VALUES(big_analytics_full[салон]), big_analytics_full_arrival[салон])` — без relationship между таблицами.

## Текущие особенности

**Маркар:** телефонный JOIN не используется: телефоны в CRM/gsheet разного формата.
Рабочий ключ — ID заявки из `link`; строки gsheet без пары в `raw_data.leads_all`
добавляются отдельной веткой `marcar_orphans` по `source`-домену. Если `source` не
является известным Авто-доменом, matched-лиды/звонки остаются на DB-домене заявки.

**Timing step13:** подстадии пишутся в `ad_analytics.data_quality_log` как
`step13.<stage>`: создание shadow-таблицы, загрузка целевых колонок, каждая ветка
`branch.*`, swap и финальный rowcount.

**Пиксель и Direct:** визитная ось не несёт расход/клики/показы. Direct/SEO/посевные
лиды и звонки считаются через lead/call-ветки по реальной дате визита; дробная
пиксельная атрибуция переносится отдельной веткой `pixel` с date-shift по долям
визит-лидов.

**Слайсеры домен/регион/специалист не фильтруют arrival:** TREATAS только по `салон`.
Остальные фильтры страницы (город, регион, специалист, домен) применяются к `big_analytics_full`,
но не передаются в `big_analytics_full_arrival`. При необходимости — добавить TREATAS по каждой колонке,
учитывая разницу имён (`направление` → `direction`, `домен` → `domain`).
